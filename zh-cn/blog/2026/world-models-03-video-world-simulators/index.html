为什么重要

第 1 篇把世界模型介绍为针对单个任务训练的小型学习式模拟器，第 2 篇则搭建了生成模型的工具箱。2023 到 2025 年间，这两条路线汇合了：在互联网规模数据上训练的视频生成器开始被描述为、也被用作世界模拟器（world simulator）：给它一帧画面和一串动作，它就渲染出接下来发生的事情。对于做图形学的人来说，这是一个惊人的转变：一个学习得到的模型一次性取代了整个游戏引擎（状态更新、物理和渲染）。本文梳理关键系统，解释其中唯一真正全新的要素（从无标注视频中学到的潜在动作（latent actions）），并坦诚说明这些模型目前仍做不到什么。

前置知识

  • 第 1 篇和第 2 篇（RSSM 与想象；tokenizer、自回归 Transformer、潜在扩散、无分类器引导、DiT）。
  • 熟悉视频张量 $(T, H, W, C)$，以及游戏循环（game loop）的概念（输入、状态更新、渲染）。

1. 从视频预测到世界模拟

视频模型针对片段 $x_{1:T}$ 和条件 $c$（文本、首帧）学习 $p_\theta(x_{1:T} \mid c)$。世界模拟器还额外需要：

  1. 交互性（interactivity）：一种分解 $p_\theta(x_{t+1} \mid x_{\le t}, a_{\le t})$，能够随着动作到来逐帧推进，而不是只能一次生成整个片段。
  2. 可控性（controllability）：动作必须真正决定结果（“向左移动”的输入会让角色向左移动），并且动作空间必须有意义。
  3. 一致性与记忆（consistency and memory）：移开视线再看回来时世界必须保持不变，物体必须持续存在，推演（rollout）在几百帧之后也不能漂移成噪声。
  4. 合理的动力学（plausible dynamics）：物体像在目标领域（游戏规则或真实物理）中那样下落、碰撞和遮挡。
  5. 速度：要用于交互，就必须实时运行，通常为每秒 20-30 帧。

下面的每个系统都解决了这些需求中的不同子集。一种简洁的比较方式如下：

系统 年份 领域 生成器 动作输入 能否实时交互？
GAIA-1 (Wayve) 2023 驾驶 tokenizer + 自回归 Transformer + 视频扩散解码器 自车速度/曲率、文本 否
UniSim (Google DeepMind et al.) 2023 机器人、人类、导航 视频扩散 文本或底层控制 否
Sora (OpenAI) 2024 通用视频 基于时空 patch 的扩散 Transformer 无（文本/图像/视频提示） 否
Genie (Google DeepMind) 2024 2D 平台游戏、机器人视频 VQ tokenizer + MaskGIT 动力学 学习得到的潜在动作 否（约 1 fps）
GameNGen (Google) 2024 DOOM 微调的 Stable Diffusion 键盘动作 是，单个 TPU 上 20 fps
Genie 2 (Google DeepMind) 2024 由图像生成 3D 世界 自回归潜在扩散 键盘/鼠标 否（研究原型）
Cosmos (NVIDIA) 2025 物理 AI（机器人、驾驶） 扩散与自回归世界基础模型 通过后训练 取决于具体模型
Genie 3 (Google DeepMind) 2025 由文本生成通用 3D 世界 未公开 导航 + 文本“世界事件” 是，720p 下 24 fps（据官方公告）

2. Sora：“视频生成模型作为世界模拟器”

OpenAI 于 2024 年 2 月发布的技术报告 “Video generation models as world simulators” 在较高层次上描述了 Sora（报告明确省略了模型与实现细节）：

  • 一个视频压缩网络（video compression network）把原始视频映射到在空间和时间上都经过压缩的潜在表示（第 2 篇第 6 节）。
  • 潜在表示被切分成时空 patch（spacetime patches），作为扩散 Transformer（diffusion Transformer）的 token（第 2 篇第 9 节）。由于模型看到的是长度可变的 patch 集合，它可以在视频原生的时长、分辨率和宽高比上训练，而不必把所有视频都裁成固定的正方形。
  • 训练视频使用一个描述性字幕模型重新标注（即 DALL·E 3 中的技术），用户的简短提示则由语言模型进行扩写。

报告的核心主张就写在标题里：扩大视频生成的规模会产生涌现的模拟能力（emergent simulation capabilities），报告列举了相机运动下的 3D 一致性、长程连贯性与物体恒存性（有时能做到）、改变世界状态的简单交互（画家留下笔触、汉堡上的一口咬痕），以及“模拟数字世界”（它能在用一个基础策略控制玩家的同时渲染 Minecraft）。同一份报告也列出了失败之处：它无法准确模拟许多基本交互的物理过程，例如玻璃碎裂；吃东西之类的交互也并不总能产生正确的状态变化。

把 Sora 当作世界模型来引用时，有两点值得注意。第一，它不以动作为条件（not action-conditioned）：你无法用控制输入逐步推进它，因此它只是弱意义上的模拟器，即“用场景描述去提示它”。第二，证据是定性的（经过挑选的样例）；第 5 篇会讨论检验这类主张的基准测试，它们发现模型对物理的理解相当有限。

3. Genie：从无标注视频学习生成式交互环境

3.1 问题：互联网视频没有动作

要训练 $p(x_{t+1} \mid x_{\le t}, a_t)$ 就需要动作标签，但互联网上绝大多数游戏视频和真实世界视频都没有这些标签。Genie（Bruce et al., “Genie: Generative Interactive Environments”, ICML 2024, arXiv:2402.15391）从约三万小时的 2D 平台游戏视频中学习了一个可控的世界模型，完全不需要动作标签。其 11B 参数的模型由三部分组成：

  1. 一个时空视频 tokenizer（spatiotemporal video tokenizer）（一个 VQ-VAE，采用内存高效的 ST-Transformer，交替进行空间注意力和因果时间注意力），为每一帧生成离散 token $z_t$。
  2. 一个潜在动作模型（latent action model, LAM），推断相邻两帧之间的离散动作 $\tilde a_t$（第 3.2 节）。
  3. 一个动力学模型（dynamics model），即 MaskGIT 风格的 ST-Transformer，根据过去的 token 和潜在动作预测下一帧的 token：$p(z_{t+1} \mid z_{\le t}, \tilde a_{\le t})$。

推理时 LAM 会被丢弃。用户（或智能体）在每一步从潜在动作中选择一个，再由动力学模型和 tokenizer 解码器渲染结果。Genie 可以用从未见过的图像（包括草图和照片）作为提示，把它们变成可玩的 2D 世界。同样的方法在机器人视频上训练后，为机械臂学到了一致的潜在动作；论文还表明，从专家视频中推断出的潜在动作可以用很少的标注样本为一个未见过的游戏训练策略。

3.2 潜在动作模型

LAM 是一个中间带有信息瓶颈（information bottleneck）的自编码器。编码器看到过去的帧 $x_{1:t}$ 以及下一帧 $x_{t+1}$，输出一个连续向量，该向量被量化为数量极少的码字之一（Genie 使用 $\lvert \mathcal{A} \rvert = 8$）。解码器必须仅凭过去的帧和这个码字重建 $x_{t+1}$：

\[\tilde a_t = \mathrm{VQ}\big(\mathrm{Enc}_\phi(x_{1:t}, x_{t+1})\big) \in \lbrace e_1, \dots, e_{\lvert\mathcal{A}\rvert} \rbrace,\qquad \mathcal{L}_{\mathrm{LAM}} = \big\lVert x_{t+1} - \mathrm{Dec}_\psi(x_{1:t}, \tilde a_t) \big\rVert^2 + \mathcal{L}_{\mathrm{VQ}} .\]

由于过去的帧已经提供给了解码器，利用这个 3 比特瓶颈最划算的方式，就是编码发生了什么变化且无法从过去预测的部分，而在游戏中这主要就是玩家的输入。同样的原理也出现在 LAPO（Schmidt & Jiang, “Learning to Act without Actions”, ICLR 2024, arXiv:2312.10812）中，它从 Procgen 视频中恢复潜在动作策略和世界模型，并用一个很小的标注集把潜在动作映射到真实动作。一种更早的替代方案是 VPT（Baker et al., NeurIPS 2022, arXiv:2206.11795）：在少量带标注的 Minecraft 游玩数据上训练一个逆动力学模型（inverse dynamics model），再用它为 7 万小时的互联网视频打伪标签。

潜在动作有一些已知的弱点：它们可能捕捉到并非由智能体引起的变化（相机抖动、其他角色），在不同领域之间并不对齐，而且一个小的离散码本难以很好地表达连续控制。第 8 节给出了一个可运行的玩具 LAM。

3.3 Genie 2 与 Genie 3

Genie 2（Google DeepMind 博客，2024 年 12 月）转向了 3D。它被描述为一个自回归潜在扩散模型（autoregressive latent diffusion model）：帧先经过自编码器，然后一个像 LLM 一样用因果掩码训练的大型 Transformer 动力学模型，在给定过去潜在表示和键盘/鼠标动作的条件下，通过扩散生成下一个潜在帧。模型使用无分类器引导来提升动作的可控性。以单张图像（例如来自 Imagen 3）为提示，它生成的世界可以保持长达一分钟的一致性，能记住离开视野的场景部分，并能模拟水、烟、重力和光照等效果。DeepMind 用它为其 SIMA 智能体生成评估环境。

Genie 3（Google DeepMind 博客，2025 年 8 月）由文本提示生成，是该系列中第一个可实时交互的模型：公告称其在 720p 下达到每秒 24 帧，并能在几分钟内保持一致性。它还引入了可提示的世界事件（promptable world events）：用文本指令改变正在运行的世界（天气、新的物体或角色）。公告列出了若干局限，包括智能体的动作空间有限、多智能体交互困难、对真实地点和文字的渲染不准确，以及交互时长有限。公告发布时并未公开论文或架构细节，因此应把具体的能力主张视为该公司自己的说法。

4. GameNGen：把扩散模型当作游戏引擎

GameNGen（Valevski et al., “Diffusion Models Are Real-Time Game Engines”, ICLR 2025, arXiv:2408.14837）提出了一个范围很窄但很尖锐的问题：神经网络能否本身就是一个复杂游戏的游戏引擎？它在单个 TPU 上以每秒 20 帧交互式地模拟 DOOM，单次会话可持续数分钟。其方法分为两个阶段：

  1. 数据：一个强化学习智能体学习玩 DOOM，其所有训练回合（包括早期表现很差的回合，它们提供了多样化的覆盖）都被记录为（帧，动作）序列。
  2. 模型：把 Stable Diffusion v1.4 改造成下一帧预测器。文本条件被替换为最近若干动作的嵌入，过去的帧由自编码器编码后沿通道维度与加噪的潜在表示拼接：
\[p_\theta\big(x_{t+1} \mid x_{t-N+1:t},\ a_{t-N+1:t}\big)\]

其中 $N$ 是上下文中过去帧与动作的数量（论文中为 64）。

决定性的技巧是上下文噪声增强（noise augmentation of the context）。训练时，用随机强度的高斯噪声破坏作为条件的帧，并把该噪声强度作为输入提供给模型。于是模型学会纠正自身上下文中的误差，从而阻止自回归漂移，否则这种漂移会在几秒内毁掉推演。作者还微调了潜在解码器以减少 HUD 中的伪影，采样只用 4 步 DDIM，并报告下一帧 PSNR 为 29.4（与有损 JPEG 相当）；人类评估者区分真实游戏与模拟的短片段时，准确率仅略高于随机猜测。

GameNGen 的局限同样富有启发性：由于只有约三秒的视觉上下文，它没有长期记忆。屏幕上不可见的游戏状态（例如你去过哪些区域）只能通过 HUD 显示的内容得以保留。DIAMOND（第 1 篇）在 CS:GO 上也得出了类似结论。

5. 以动作为条件的真实世界模拟器

5.1 UniSim

UniSim（Yang et al., “Learning Interactive Real-World Simulators”, ICLR 2024 Outstanding Paper, arXiv:2310.06114）瞄准真实世界。它的洞见在于，不同数据集携带不同种类的“动作”：图像-字幕数据中的文本、机器人数据中的电机指令、导航数据中的相机运动、人类活动的语言描述。UniSim 把它们全部统一为同一个视频扩散模型的条件，该模型在给定历史和动作的情况下预测下一段视频。论文随后完全在模拟器内部训练了（a）一个高层视觉-语言规划器和（b）一个底层强化学习策略，并展示了向真实机器人的零样本迁移。这是视频世界模型可以作为训练用模拟器、而不仅仅用于生成好看视频的最清晰的证明。

5.2 面向驾驶的 GAIA-1

GAIA-1（Hu et al., Wayve, arXiv:2309.17080, 2023）是一个面向自动驾驶的生成式世界模型。视频、文本和自车动作被编码为 token，一个自回归 Transformer 世界模型预测下一组图像 token（把未来预测当作下一个 token 预测），再由一个独立的视频扩散解码器渲染高分辨率帧。以动作为条件使人们可以提出反事实问题（“如果车向左转会怎样？”），文本提示则可以改变天气或时间。驾驶是一个天然的应用场景，因为罕见而危险的场景正是模拟器应该生成的东西。

5.3 NVIDIA Cosmos

Cosmos（NVIDIA, “Cosmos World Foundation Model Platform for Physical AI”, arXiv:2501.03575, 2025）把世界模型定位为物理 AI 的基础模型（foundation models）。该平台包括视频筛选管线、连续和离散的 Cosmos tokenizer、扩散和自回归两种形式的预训练世界基础模型（world foundation models）、安全护栏，以及把通用模型专门化到相机控制、机器人操作和自动驾驶的后训练示例。这些模型以 NVIDIA Open Model License 发布（github.com/NVIDIA/Cosmos）。预期的工作流是“在广泛的视频上预训练一次，再在你的机器人或汽车数据上后训练”，这与 LLM 的适配方式如出一辙。如果你想在一个大型开放视频世界模型上做实验，Cosmos 是一个很好的起点。

6. 让自回归视频推演保持稳定

所有交互式模型都是逐帧（或逐块）生成，并以自身的输出为条件，因此它们以一种严重的形式面临第 1 篇中提到的误差累积问题。你会反复遇到以下技术：

  • 上下文噪声增强（context noise augmentation）（GameNGen、Genie 2 类模型）：用被破坏的上下文进行训练，并把破坏程度告诉模型。
  • Diffusion Forcing（Chen et al., NeurIPS 2024, arXiv:2407.01392）：训练时为序列中的每一帧赋予其独立的噪声强度。以这种方式训练的因果模型可以在过去帧干净或仅略带噪声的情况下对后续帧去噪，保持未来的不确定性并稳定长时推演；它还支持对整条未来轨迹施加引导，用于规划。
  • 带 KV 缓存的因果注意力（causal attention with KV caching），使每一新帧的计算量保持恒定；以及步数蒸馏（step distillation）（少步或单步采样器），以达到实时速率。
  • 记忆机制（memory mechanisms）：更长的上下文窗口、对过去帧的压缩记忆、按相机位姿检索帧，或场景的显式 3D 表示。最后一种方案直接引向第 4 篇。

7. 仍然缺少什么

  • 长时程一致性与记忆。 转两圈身，房间就变了。像素空间模型除了上下文窗口之外没有任何持久状态；几分钟级别的一致性是前沿主张，几小时级别则尚未解决。
  • 物理。 Kang et al.（”How Far is Video Generation from World Model: A Physical Law Perspective”, ICML 2025, arXiv:2411.02385）在合成的 2D 物理数据上训练视频扩散模型，发现其在分布内的泛化近乎完美，但在分布外失败：模型表现得像基于案例的（case-based）检索（模仿最接近的训练样例），而不是学到了规律。Physics-IQ（Motamed et al., WACV 2026, arXiv:2501.09038）发现，当前视频模型的物理理解极为有限，且与视觉真实感无关。第 5 篇会再回到评估问题。
  • 可控性与动作空间。 一个游戏里是键盘动作，另一个里是潜在动作，别处又是机器人关节指令：不存在共享的动作接口，这限制了迁移。
  • 因果与相关。 在被动视频上训练的模型可能会学到“雨伞导致下雨”。干预数据（动作）有帮助，但大多数视频都没有动作。
  • 算力。 高分辨率的实时生成需要大量蒸馏和专用硬件，而训练预算超出了大多数实验室的承受范围。
  • 评估。 FVD 和视觉质量指标几乎无法说明一个模拟器是否适合用来训练智能体（第 5 篇）。

8. 代码：一个玩具潜在动作模型

下面的脚本把潜在动作的思想具体化。一个点在 $12 \times 12$ 网格上按五种隐藏动作（不动、上、下、左、右）移动。一个带 8 路离散瓶颈的 LAM 只用帧对 $(x_t, x_{t+1})$ 训练；之后我们检查学到的码字是否与隐藏动作对齐，并通过反复输入选定的码字来“玩”这个世界模型。为了在这么小的规模下稳定训练，瓶颈采用直通（straight-through）Gumbel-softmax，而不是 Genie 的 VQ（两者都能在保留梯度的同时给出离散码字）；编码器是带全局池化的卷积网络，即具有平移不变性。它在 CPU 上大约两分钟即可运行完毕。

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
G, K = 12, 8                                      # grid size, number of latent actions
MOVES = torch.tensor([[0, 0], [-1, 0], [1, 0], [0, -1], [0, 1]])   # stay, up, down, left, right

def render(pos):
    ys, xs = torch.meshgrid(torch.arange(G), torch.arange(G), indexing="ij")
    d2 = (ys[None] - pos[:, 0, None, None]) ** 2 + (xs[None] - pos[:, 1, None, None]) ** 2
    return torch.exp(-d2.float() / 0.5).reshape(len(pos), -1)

def sample_transitions(n):
    pos = torch.randint(1, G - 1, (n, 2))
    act = torch.randint(0, 5, (n,))
    nxt = (pos + MOVES[act]).clamp(0, G - 1)
    return render(pos), render(nxt), act

def mlp(i, o, h=256):
    return nn.Sequential(nn.Linear(i, h), nn.ReLU(), nn.Linear(h, h), nn.ReLU(), nn.Linear(h, o))

class ConvEncoder(nn.Module):
    """Translation-invariant: conv layers + global max pooling, so a code can only describe the motion."""
    def __init__(self):
        super().__init__()
        self.conv = nn.Sequential(nn.Conv2d(2, 32, 3, padding=1), nn.ReLU(), nn.Conv2d(32, 32, 3, padding=1), nn.ReLU())
        self.head = nn.Linear(32, K)

    def forward(self, x, x_next):
        h = self.conv(torch.stack([x, x_next], 1).view(-1, 2, G, G))
        return self.head(h.amax(dim=(2, 3)))

enc = ConvEncoder()
dec = mlp(G * G + K, G * G)
opt = torch.optim.Adam([*enc.parameters(), *dec.parameters()], lr=1e-3)
for step in range(3000):
    x, x_next, _ = sample_transitions(256)
    z = F.gumbel_softmax(enc(x, x_next), tau=1.0, hard=True)
    loss = F.mse_loss(dec(torch.cat([x, z], 1)), x_next) * 100
    opt.zero_grad(); loss.backward(); opt.step()
    if step % 1000 == 0:
        print(f"step {step}  loss {loss.item():.4f}")
with torch.no_grad():
    x, x_next, act = sample_transitions(5000)
    idx = enc(x, x_next).argmax(1)
    for a, name in enumerate(["stay", "up", "down", "left", "right"]):
        c = torch.bincount(idx[act == a], minlength=K)
        print(f"{name:>5}: code {c.argmax().item()}, purity {(c.max() / c.sum()).item():.2f}")
    right = torch.bincount(idx[act == 4], minlength=K).argmax()
    frame = render(torch.tensor([[6, 3]]))
    for t in range(4):
        frame = dec(torch.cat([frame, F.one_hot(right, K).float()[None]], 1))
        r, c = divmod(frame.argmax().item(), G)
        print(f"t={t + 1}: dot at row {r}, col {c}")

在这个玩具例子中，五种隐藏动作通常会以很高的纯度映射到不同的码字，反复按下“右”对应的码字会让点每步向右移动一格。可以尝试：加入第二个不受控制、随机移动的点，看看码字是否也开始编码它的运动（这是 LAM 的一种已知失效模式）；或者把码本缩小到 4，看看哪些动作会被合并。还可以把 ConvEncoder 换成作用于拼接帧的 MLP：重建损失照样下降，但码字纯度会跌到 0.2-0.3 左右（接近随机水平）。原因是解码器也能看到当前位置，于是每个码字的含义可以随网格区域而变化。只有当网络结构或训练方式强制要求时，潜在动作才会在不同状态之间保持一致，这对在多样化视频上训练的 LAM 来说是一个真实存在的问题。
